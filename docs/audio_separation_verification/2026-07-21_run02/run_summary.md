## 附：改造 v1 效果诊断（关键认知）

**核心发现**：`--segment=4 --shifts=1` 仅优化「分片推理」阶段内存峰值，**不能降低模型加载阶段的内存峰值**。

- demucs CLI 启动会启动新 Python 进程 → `import torch` (~250MB) → `from demucs.pretrained import load_model` 加载 htdemucs 模型权重 (~400MB) → 主进程 + 子进程总占用突破 512MB → 模型加载完成前就被 SIGKILL
- 这解释了为什么改造后崩溃耗时从 65 秒（有下载）降到 7-20 秒（无下载、纯加载阶段）：省下了下载时间，但加载内存压不下去

**唯一根治路径**：必须把模型常驻主进程内存（避免每次请求重新加载），或换用更轻量模型/量化模型，或升实例配额。
