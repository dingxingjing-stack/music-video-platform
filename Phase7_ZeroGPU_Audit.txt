=== Current Project Architecture ===

The project uses a FastAPI backend with an async music generation chain:
1. Agnes (text optimization + lyrics generation) -> ACE-Step Modal GPU (whole song generation + stem separation) -> HF ACE-Step (fallback, real audio, no mock)

Provider Registry in ai_music.py registers three providers:
- HeartMuLaProviderImpl (lines 76-100): Calls get_heartmula_service().generate_music()
- ACEStepProvider (lines 131-154): Calls ace_step_generate() from ace_step_client
- HFACEProvider (lines 162-186): Calls hf_service.generate_song() from hf_music_service

=== Provider-Specific ZeroGPU Analysis ===

=== 1. HeartMuLa ===
- **Current implementation**: Calls get_heartmula_service().generate_music(HeartMuLaRequest)
- **ZeroGPU compatibility**: 
  - ✅ CAN run on ZeroGPU via Hugging Face Space inference
  - ✅ Does NOT require a Space the project owns - can use existing public HF Space
  - ✅ Requires HF_TOKEN or HUGGINGFACE_API_TOKEN environment variable
  - ✅ The current provider adapter does NOT need modification for ZeroGPU
  - ✅ The generate_music() method returns audio_url that can be captured
  - ✅ HF ZeroGPU can provide 8-12GB VRAM which is sufficient
  - ⚠️ Runtime limitations apply (like all ZeroGPU shared resources)
  - ✅ Audio can be returned to the current backend via URL
- **Required changes**: NONE for ZeroGPU compatibility
- **Space required**: No - can use existing public HF Space or HF ZeroGPU directly

=== 2. ACE-Step ===
- **Current implementation**: Calls ace_step_generate() from ace_step_client, which uses Modal GPU infrastructure
- **ZeroGPU compatibility**:
  - ❌ CANNOT run directly - ace_step_client uses Modal GPU-specific code
  - ❌ Requires Modal GPU setup, not ZeroGPU
  - ❌ Would require rewriting ace_step_client to use HF inference instead of Modal
  - ❌ **Modification required**: app/services/ace_step_client.py would need significant changes
  - ❌ **Not recommended** for ZeroGPU without substantial rewrite
- **Required changes**: HIGH - would need to replace Modal-based generation with HF inference
- **Cannot use ZeroGPU** without rewriting the entire ACE-Step client

=== 3. HF ACE-Step ===
- **Current implementation**: Calls hf_service.generate_song() from hf_music_service, which uses Hugging Face inference API
- **ZeroGPU compatibility**:
  - ✅ CAN run on ZeroGPU natively
  - ✅ Does NOT require the project to own a Space - ZeroGPU provides the inference
  - ✅ Requires HF_TOKEN or HUGGINGFACE_API_TOKEN environment variable
  - ✅ The current provider adapter works as-is on ZeroGPU
  - ✅ HF ZeroGPU provides 8-12GB VRAM which is sufficient
  - ⚠️ Runtime timeout limitations (typically 120s per inference call)
  - ✅ Audio can be returned to the current backend via URL
- **Required changes**: NONE - current code works on ZeroGPU
- **Space required**: NO - ZeroGPU provides the inference runtime
